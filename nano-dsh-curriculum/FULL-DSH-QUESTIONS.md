# 完整 DSH 问题池备份

这份文件备份一次面向完整 DeepSeek Harness（DSH）的社区问题发散。它不表示 Nano DSH 的范围、优先级或章节安排；Nano 筛选只在 [NANO-DSH-CANDIDATES.md](NANO-DSH-CANDIDATES.md) 中进行。

DSH 的公开 Discussions 尚无足够内容用来统计真实社区优先级，因此以下问题来自对 DSH 特性和常见 Agent 使用场景的推断。[官方仓库](https://github.com/deepseek-ai/deepseek-harness) · [官方 Discussions](https://github.com/deepseek-ai/deepseek-harness/discussions)

## 认识 DSH

### 1. 同一个模型，为什么换一个 Harness 后，能力和表现会差这么多？

带出模型之外的 Agent Loop、提示词、工具、上下文和策略。

### 2. DSH 只能运行 DeepSeek 模型吗？哪些设计是 DeepSeek 特有的，哪些是通用的？

这是项目名称自然引发的问题。

### 3. “一切皆插件”到底意味着什么？模型调用、工具、记忆和运行方式真的都能替换吗？

带出 DSH 的核心设计，以及插件如何安装、撤销和组合。

## Agent 如何获得能力

### 4. 为什么 DSH 允许 Agent 编写一段代码来组合工具，而不只是一次调用一个工具？

带出 Code Mode：循环、条件、并行和数据处理可以在一次代码运行中完成。

### 5. 模型每次收到请求时，究竟看到了什么？

带出系统提示词、会话历史、工具说明、Skill 和动态上下文如何共同组成模型请求。

### 6. 工具、Skill、Plugin 和 Preset 有什么区别？想教 Agent 一项新能力时应该改哪一层？

这是扩展 DSH 时容易产生的真实困惑。

## 长程与复杂任务

### 7. 一个任务需要几十轮甚至跨越进程重启时，DSH 怎样让 Agent 持续朝同一个目标推进？

带出 Goal、Todo、自动续行、完成条件和轮次上限。

### 8. Agent 到底把“记忆”存在哪里，为什么旧任务能够恢复、回放或从中间分叉？

带出 Session Log，但问题本身不要求读者预先理解事件溯源。

### 9. 对话和工具结果越来越多，DSH 怎样避免撑爆上下文，又尽量不忘记关键进展？

带出工具结果裁剪、历史压缩、摘要检查点和近期内容保留。

### 10. 面对复杂任务，什么时候继续由主 Agent 做，什么时候开后台任务、派 Subagent 或编写 Workflow？

对应用户在不同任务编排方式之间的选择。

### 11. Agent 正在工作时，用户还能怎样打断、纠偏或追加要求？

带出 follow-up、steer 和 inject 的不同语义。

### 12. Agent 能不能在未来某个时间主动回来继续工作？

带出持久 Schedule、会话唤醒和交付限制。

## 控制与可靠性

### 13. 模型说要运行命令、修改文件时，它到底能碰到什么，谁能拦住它？

带出权限、审批、文件策略和进程沙箱。

### 14. 模型失败、工具卡住或进程崩溃时，任务如何收尾和恢复，而不重复已经完成的操作？

带出取消、超时、持久化检查点和中断轮次恢复。

### 15. 用户怎样看清 Agent 每一步看到了什么、调用了什么，以及为什么停止？

带出可重放日志、请求记录、工具记录和交互式执行轨迹。

## DSH 最有辨识度的延伸

### 16. 既然一切都是插件，Agent 能不能检查并改造自己的运行时？

带出 Agent 为自己创建、安装、更新或卸载能力。

### 17. 允许 Agent 自我修改以后，怎样避免“获得新能力”变成“绕过原有限制”？

重点是自我扩展的信任与授权，区别于普通工具权限。

### 18. 插件和上下文如此动态，会不会让提示词越来越大、缓存失效、速度变慢、成本升高？

带出按需 Skill、稳定工具目录、上下文压缩和 KV Cache 设计。

## 问题之间的关系

- 1 是总览式问题，5 是其中关于模型请求的具体机制。
- 7 → 8 → 9 → 14 可以组成长程任务故事线。
- 3 → 6 → 16 → 17 可以组成从插件到自我修改的故事线。
- 10 与 12 都涉及任务调度，但一个讨论分工，一个讨论时间。
- 13 与 17 都涉及安全，但分别面向普通工具和自我修改。
- Provider、事件分发、注册撤销和作用域适合作为答案中的实现机制，不适合单独成为大众问题。
