# The Agent Installs Its Own Tool

Chapter 4's log can explain what happened, yet it does not add a capability. Suppose an Agent needs to count the words in a piece of text and the current `Context` has no `word_count` tool. Guessing tool names or repeatedly calling unrelated tools consumes Steps without closing that capability gap.

DSH treats this situation as a controlled runtime change: **inspect the current capabilities and interfaces, mount a temporary plugin, call its new tool to verify the result, and release the plugin when the task ends.** This path brings the first four chapters together: the Agent Loop starts the action, request projection carries the current tools, the plugin lifecycle manages entry and exit, and the Session Log records the process.

`runtime-tools.ts` begins with the shape of a dynamic plugin and the entry point for `runtimeToolsPlugin()`. The following implementation works from one definition table, making three states easy to distinguish: plugin code is registered, the plugin is running, or the plugin has been released.

## 5.1 Confirm the Gap Before Deciding What to Add

`cordis_inspect` returns the plugins, services, tools, prompts, and dependencies in the current `Context`. **Confirm what is missing before deciding what to add.** The Agent uses this result to establish that `word_count` is absent, then decides what the plugin must provide. The baseline capability graph matters too: it gives a comparable state from before the change, so the model does not mistake an existing capability for a gap.

Runtime Tools also needs its own lifecycle. Its definition table holds dynamic plugins. When Runtime Tools unloads, it stops any still-running plugins in reverse order and clears the definitions. It also registers the inspection tool and a Prompt that tells the Agent when to inspect, define, and run a plugin. These preparations give a temporary extension a definite entry and exit.

## 5.2 Defining Code and Mounting a Capability Are Different Moments

After inspection confirms the gap, the Agent submits a plugin name, purpose, and JavaScript code through `cordis_define`. **Defining code and mounting a capability happen at different moments.** The function compiles the code and saves its definition in the table. The tool catalog does not change yet. `cordis_run` retrieves the definition, instantiates a Plugin, and calls Chapter 3's `context.mount()`. Only after mounting succeeds does the new tool join the current `Context`.

The distinction has a practical purpose. Definition can report whether code is loadable; mounting can report whether the plugin actually changed the runtime. A failure therefore has a precise location. The full DSH offers `cordis_inspect`, `cordis_mount`, and `cordis_unmount`; temporary plugins act on the current process and disappear when they unload or the process ends.

## 5.3 Verification and Release Close the Change Loop

After the plugin mounts, `dynamic:word_count` appears in the plugin list and `word_count` in the tool list. **The new tool becomes visible from a later model request onward.** A new request reads `Context` again, so its Tool Schema gains the tool name and argument rules; a request already sent remains unchanged.

The Agent calls `word_count` and receives `words: 3`. That result proves that the new capability has passed through the Agent Loop and completed the task.

<!-- evidence {"id":"m05-verified","tab":"events","eventType":"tool/result","eventOccurrence":4,"label":"A tool result verifies the new capability","description":"Inspect the word_count result to confirm that the new tool completed one real call."} -->

After verification, `cordis_stop` calls the unload function saved during mounting but retains the definition for a later rerun. `cordis_undefine` first stops a running plugin, then removes its definition. Supporting helpers compile code, instantiate plugins, and read arguments so the Tool bodies can focus on state transitions. `node:vm` loads only trusted teaching samples here; a deployment still needs explicit permissions and an enablement boundary.
