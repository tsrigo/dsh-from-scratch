# Use a Goal to Continue Work in the Same Session

The Agent Loop in Chapter 1 manages one Turn: it receives the input for that Turn, repeatedly requests the model and executes tools, and stops when the model makes no more Tool Calls. The end of a Turn means that this execution has stopped, although a long-term goal may still require more work.

DeepSeek Harness stores a Goal as persistent state within the same Session. A Goal records its `objective`, `phase`, the number of Goal Rounds already started, and the maximum number of Rounds. When the Agent is idle, the Goal Round Driver checks the Goal. If its `phase` is `active`, continuation is enabled, and Rounds remain, the driver appends a `<goal_round>` message containing the Goal and Round number to the same Session, then starts a regular Turn. The new Turn continues with the current workspace, Tool Results, and session history.

Nano DSH condenses these relationships into `LongTaskRunner`. This chapter uses a task that organizes three release notes: the first Round gathers two existing items, and the second completes the last item and delivers the result. `LongTaskRunner` stores the Goal, its status, and the Round count in `LongTaskState`. It stores the name and input for each Round in two `RoundDefinition` objects, then starts a regular Agent Turn through `runRound`. This minimal example shows how a Goal spans multiple Turns and who decides whether to continue or stop after each Round.

## LongTaskRunner Stores the Goal and Starts a Round

`LongTaskState` stores the `objective`, `status`, number of Rounds started, maximum number of Rounds, and the reason for the latest status change. At startup, `LongTaskRunner` writes a Goal creation event. While the status is active and another Round is available, it retrieves the next `RoundDefinition`, records the Round number and name, and calls `runRound`.

After each Round, `runRound` returns a `RoundResult`. `progressed` indicates whether the Round produced the expected Tool Result or workspace change. `completed` indicates whether the entire Goal is complete. `blockedReason` records why execution cannot continue. Nano DSH uses these three fields to update the status to `completed`, `blocked`, or `max-rounds`. If the Round made progress but did not complete the Goal, the status remains `active` and the next Round starts.

The full DeepSeek Harness uses `active`, `paused`, `blocked`, and `complete` as values of the Goal's `phase`. The Goal Round Driver decides whether to admit the next Round from the `phase`, continuation setting, and Round limit. Nano DSH's `LongTaskState` and `RoundResult` gather the same continue-or-stop decisions into a control flow that is easier to read.

## The Next Round Reuses Existing Records in the Same Session

`LongTaskRunner` does not request the model or execute tools directly. At the start of each Round, it calls the externally supplied `runRound` function. The tutorial's `runRound` starts a new Agent Turn with the same Agent, Context, and Session Log, so plugins, messages, Tool Results, and workspace changes from the previous Round remain available.

The Goal Round Driver in the full DeepSeek Harness also continues in the same Session. It appends the Goal and Round number for each Round so the model can decide what to do next from the existing history. For a deterministic demonstration, Nano DSH provides two stage instructions: collect the existing information, then complete and deliver it. The program can therefore check the expected result of each Round automatically.

Nano DSH writes Goal creation, Round starts, and the final status change to the Session Log. The Tools, Prompts, model responses, and Tool Results used in each Round are written to the same log. Goal events explain why the coordinator continues or stops, while Turn and Step events record what the Agent completed.

The full DeepSeek Harness uses `goal/change` to store Goal snapshots and a `revision`, and uses `user/message` with the Goal as its source to record each admitted Goal Round. Goal state and execution history continue to use the same Session Log.

## Check Whether to Continue After Each Round

The full DeepSeek Harness checks the Goal when the Agent is idle. If the model has updated the `phase` to `complete`, `blocked`, or `paused`, the driver stops continuation. If the Goal remains `active`, continuation is enabled, and Rounds remain, the driver starts the next Round. The model reports completion or blockage through `update_goal`, and the Session Log stores every status change.

Nano DSH expresses these checks as explicit branches in `LongTaskRunner`. It stops when the Goal is complete, the current Round makes no expected progress, the execution function returns a blocked reason, the next stage is missing, or the maximum number of Rounds has been reached. It continues when the current Round makes progress and the Goal remains incomplete. The release-notes example first records the two items already found, then starts the second Round to complete the third and updates the Goal to `completed`.

Chapter 6 adds a continuation mechanism outside the Agent Loop. The Goal stores state across Turns, a Round represents one continuation, the Session Log preserves existing progress, and the driver decides after each Round whether to start another Turn.
