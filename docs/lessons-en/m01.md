# The Agent Loop Repeats Steps Based on Model Feedback

A single model call produces one response. When an Agent handles a task, the model may first need to identify missing information, call a tool to obtain it, and then choose the next action based on the result. The model decides how many Tool Calls it needs during execution as results become available. The runtime therefore repeats a set of steps until the model returns a final response.

## The Model Chooses Actions, and the Harness Validates and Executes Them

DeepSeek Harness (DSH) calls one continuous execution a Turn. A Turn begins when the Agent receives a batch of approved inputs and ends when those inputs no longer produce follow-up work. Nano DSH uses a single user message as that batch. Each model request within a Turn, together with the tool execution it triggers, forms a Step.

At the start of each Step, the Harness combines the system rules, current tools, existing history, and step-specific instructions into one request, then sends it to the model. The model can return plain text or a set of Tool Calls. Each Tool Call contains a tool name and arguments, which the Harness uses to start the corresponding operation.

When the Harness receives a Tool Call, it looks up the tool, validates the arguments, and executes it. Unknown tools, invalid arguments, and execution errors are all converted into structured results that the model can read. The model chooses the action. The runtime determines whether that action can be executed and carries it out. The tool interface defines the boundary between these responsibilities.

## Tool Results Enter the Next Request

The task may still require more work after a tool finishes. The Harness adds the Tool Result and its call ID to the history, then begins the next Step and requests another model response. The model can read both the Tool Call it issued and the actual result returned by the runtime. It can then revise its plan, call another tool, or provide a final answer.

## Turns, Steps, and Stop Conditions

Each call to Nano DSH's `runTurn()` accepts one user message and executes multiple Steps within the same Turn. When the model returns a Tool Call, the Harness executes the tool and proceeds to the next Step. When the model returns final text, the current Turn ends. This path shows the complete cycle of model requests, tool execution, and result feedback.

Full DSH checks at the end of each Step whether the current Turn still has pending Tool Results or new inputs. Nano DSH limits the number of Steps in a Turn. It returns tool failures to the model as results so the model can adjust its approach, and it terminates the run explicitly when the limit is reached. The Provider, which adapts model services, converts the unified request into the format required by a specific model interface and handles streamed responses. The Agent Loop advances the Turn and its Steps.

The DSH Agent Loop assembles a request, calls the model, validates and executes tools, and appends results in sequence. It then continues or stops based on the new model output.
