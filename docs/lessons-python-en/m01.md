# The Agent Loop Repeats Steps Based on Model Feedback

A single model call produces one response. When an Agent handles a task, the model may first need to identify missing information, call a tool to obtain it, and then choose the next action based on the result. The number of Tool Calls cannot be determined in advance, and a fixed workflow cannot cover every choice the model may make based on the results. The runtime therefore needs to repeat a set of steps.

## The Model Chooses Actions, and the Harness Validates and Executes Them

A Turn represents one user task. DeepSeek Harness (DSH) first combines the system rules, current tools, existing history, and step-specific instructions into one request, then sends it to the model. The model can return plain text or a set of Tool Calls that contain names and arguments. A Tool Call only describes an action to execute. It does not execute code directly.

When the Harness receives a Tool Call, it looks up the tool, validates the arguments, and executes it. Unknown tools, invalid arguments, and execution errors are all converted into structured results that the model can read. The model chooses the action. The runtime determines whether that action can be executed and carries it out. The tool interface defines the boundary between these responsibilities.

## Tool Results Enter the Next Request

The task may still require more work after a tool finishes. The Harness adds the Tool Result and its call ID to the history, then begins the next Step and requests another model response. The model can read both the Tool Call it issued and the actual result returned by the runtime. It can then revise its plan, call another tool, or provide a final answer.

The second retains the original rules and question, then appends the Tool Call and query result. This addition lets the Agent Loop use the execution result when choosing the next action.

## Turns, Steps, and Stop Conditions

In this tutorial implementation, a Turn represents one user task. Each model request and the tool execution it triggers form a Step. A Turn can contain multiple Steps. When the model continues to call tools, the Harness proceeds to the next Step. When the model stops calling tools, the current response ends the Turn.

The loop also needs runtime limits. Tool failures are returned to the model as results so the model can adjust its approach. When the number of consecutive Steps reaches the limit, the Harness terminates the run explicitly to prevent unbounded resource consumption. The Provider, which adapts model services, only converts the unified request into the format required by a specific model interface. It can be replaced and does not control the Agent Loop.

The DSH Agent Loop assembles a request, calls the model, validates and executes tools, and appends results in sequence. It then continues or stops based on the new model output.
