# Use Goals and Rounds to Advance One Task in Stages

The Agent Loop in Chapter 1 manages one Turn: it receives the task for that Turn, repeatedly requests the model and executes tools, and stops when the model makes no more Tool Calls. The end of a Turn means that this interaction has stopped, although a long-term goal may still require more work. A shopping-cart repair task can be divided into three stages: diagnosis, repair, and verification and delivery. Each stage starts a separate Turn.

DSH adds a continuation function outside the Agent Loop and uses a Goal and Rounds to store state across Turns. The Goal stores the objective of the complete task, its current status, and its Round limit. A Round represents one stage, such as diagnosis or verification. One Round can start a regular Agent Turn, one Turn can contain several Steps, and each Step corresponds to one model request and its Tool Results. The Goal, Round, Turn, and Step respectively identify the complete task, the current stage, the task assigned to this Agent run, and the action taken in one model interaction.

## run_long_task Decides Whether to Start the Next Round

The Goal stores its `objective`, `status`, the number of Rounds already started, the maximum number of Rounds, and the reason for the latest status change. `run_long_task` starts another Round only while the status is `active` and the Round limit has not been reached. At the start of each Round, it takes the current task from a predefined set of stage instructions and passes both the same long-term Goal and this stage instruction to `run_round`. File access, tool invocation, and result handling can still use the mechanisms from the first five chapters.

In this minimal Python implementation, `run_round` returns a result string. If the string contains `accepted`, the Goal status becomes `completed`. If it contains `blocked`, the status becomes `blocked`. If it contains neither, the next Round starts. When the Goal remains unfinished after reaching the Round limit, the status becomes `limit_reached`. `accepted` is an acceptance signal in a Round result, not the name of a Goal status.

## The Next Round Reuses the Same Goal and Existing Records

`run_long_task` does not request the model or execute tools directly. It receives an external `run_round` function and calls it at the start of each Round. The caller can use the same Agent, Context, and Session Log inside `run_round` to start a regular Agent Turn, so the plugins, messages, and Tool Results from the previous Round remain available. A stage instruction for one Round does not replace the long-term objective stored in the Goal.

## Continuation Requires Explicit Stop Conditions

A continuation function needs explicit stop conditions so that it does not start new Turns indefinitely. This minimal Python implementation recognizes three outcomes: completion, blockage, and the Round limit. It stores the final status and reason in the Goal. Unlike the TypeScript version, it has no separate `progressed` field, so it cannot distinguish between work that still needs another Round and a Round that made no progress. A production implementation needs this check to avoid repeating ineffective Rounds.

Nano DSH currently executes multiple Rounds consecutively within one process. It does not restore a Goal after a process restart or implement scheduled wake-ups, background Jobs, or Subagents. If a task must resume after a pause, the Goal and Session Log must be written to persistent storage, and a scheduler must restart the task.

Chapter 6 adds a task coordination layer outside the Agent Loop. It stores the long-term Goal and Round count, creates a clear stage instruction for each Round, and decides whether to continue from the returned result. The minimal Python implementation handles completion, blockage, and the Round limit. The caller reuses the existing Agent state and execution record in each Round.
