# Let the Task Continue Past a Turn

Chapter 5 can add a tool during a task. A Turn still ends when the current model stops calling tools. The task may remain incomplete: after one round of organizing three release notes, the Agent may have collected only two. A different layer has to decide whether work should continue.

DSH manages long-term objectives outside the Agent Loop. **A Goal decides whether cross-Turn work continues; Turns and Steps continue to handle model requests and tool execution.** A Goal holds state that spans Rounds, while a Round is one new attempt to advance it. The Python teaching version uses a smaller `Goal` data class and `run_long_task()` to show that boundary; it updates status from the text returned by an external callback.

`scenario.py` first defines Goal status and the `run_round` callback type, then gives the shape of `Goal` and each Round's instructions. It does not hold a particular Agent, Context, or Session Log. The caller decides whether to reuse those objects for a Round. This boundary lets long-task coordination do only what it needs to do: decide whether to start another ordinary Turn.

## 6.1 A Goal Needs State That Can Be Checked Across Rounds

`Goal` keeps the objective, maximum Round count, number of started Rounds, status, and reason in one object. `ROUND_INSTRUCTIONS` predefines stages for collection, implementation, and verification. **A Goal preserves cross-Round state; a Round describes the current stage of progress.** The outer layer can read one consistent status after each Round, and its caller can use that state when recording or displaying work.

Unlike the TypeScript version, this Python minimum implementation does not automatically write a `goal/created` event or support persistence and recovery. The omission keeps the code focused on continuation decisions while identifying the record boundary that full DSH needs to supply.

## 6.2 The Next Round Still Calls the Ordinary Agent Loop

When a Goal is `active` and below its Round limit, `run_long_task()` reads the current stage instruction, increments the Round count, and calls external `run_round`. The callback receives the same long-term objective and the current instruction. It can give the Round to the same Agent, Context, workspace, and Session Log used before, leaving messages, Tool Results, and plugin changes available.

This layer does not duplicate Chapter 1's tool loop. **A Goal can start a new Turn without rewriting the Agent Loop.** It supplies the stage boundary for the next Turn; the ordinary Agent Loop continues to handle model requests, Tool Calls, and feedback. Keeping the loops separate lets the model stopping Tool Calls and the Goal continuing work be evaluated independently. `scenario.py` does not build a model request itself, so the actual message history belongs to the caller of `run_round`.

## 6.3 Continuation Must Use Observable Results

Python's `run_round` returns a result string. If it contains `accepted`, the Goal becomes `completed`; if it contains `blocked`, it becomes `blocked`; otherwise the loop continues or becomes `limit_reached` at the limit. These exits live in one loop, which updates the status and reason together.

**This version can express completion, blockage, and a limit, yet it cannot distinguish no progress from progress that still needs another Round.** The returned `Goal` is the directly inspectable result here; the function does not create Session Events by itself. The TypeScript version uses a structured `RoundResult` with `progressed`, `completed`, and `blockedReason`, and writes status changes to the Session Log. A production implementation needs observable results of this kind instead of a text-contains-word check.

## 6.4 The Six Chapters on One DSH Runtime Path

One Step completes a model-and-tool round-trip in the Agent Loop. The context layer decides which information that Step sees. The plugin runtime decides what capabilities currently exist. The Session Log saves inputs, actions, and capability changes as shared facts. Runtime Tools add a needed capability during work. Goals and Rounds decide whether work needs another Turn after the current one ends.

The Python teaching version retains the smallest interfaces along this path and explicitly leaves Service dependencies, automatic session recording, structured Round results, and persistence as extension points. Full DSH adds configuration layers, permissions, sandboxes, and more runtime providers on top of those interfaces.
