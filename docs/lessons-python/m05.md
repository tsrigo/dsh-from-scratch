# Agent 编写并挂载新的插件

本教程所说的运行时自进化，指 Agent 在执行任务期间获得新的插件和工具。Agent 先检查当前插件组成，确认能力缺口，再编写一个新的插件，把它挂载到当前 Context（插件上下文），并实际调用它提供的工具。

本章把这条过程浓缩为五个普通工具：`cordis_inspect` 查看当前插件组成，`cordis_define` 登记 Agent 编写的插件代码，`cordis_run` 挂载插件，`cordis_stop` 停止插件，`cordis_undefine` 停止插件并删除定义。Agent Loop 负责调用这些工具，Context 负责插件生命周期，Session Log 记录定义、挂载、调用和移除过程。

右侧代码用 `definitions` 字典保存插件标识、名称、用途、代码和卸载函数。每个定义先保存在字典中；只有调用 `cordis_run` 以后，它才会成为当前 Context 中正在运行的插件。

## 先列出当前插件提供的能力

`cordis_inspect` 列出当前 Context 中已经挂载的 Plugin（插件），以及这些插件提供的 Tool（工具）、Prompt（系统提示内容）和依赖关系。Agent 根据这份结果判断现有工具能否完成任务，以及新的插件需要提供什么。

实验开始时，过程日志和 Cordis 工具已经挂载，`word_count` 还不存在。Agent 先调用 `cordis_inspect` 保存当前列表，后面就能比较运行插件前后增加了什么，并确认插件停止以后，它提供的内容是否已经移除。下图是三次列表对照的起点：先确认插件列里没有 `dynamic:word_count`，工具列里也没有 `word_count`。

## Agent 定义并运行新的插件

`cordis_define` 接收插件名称、用途和一段 Python 代码。代码必须定义 `plugin_factory()` 函数，返回一个带 `name` 属性和 `setup(context)` 方法的插件对象。`cordis_define` 先用内置 `compile()` 检查代码能否通过语法编译，再生成 `dyn-<n>` 形式的插件标识，把代码保存在定义表中。定义完成并不会改变当前工具列表。

`cordis_run` 根据插件标识取出代码，在受限命名空间中用 `exec()` 执行，调用 `plugin_factory()` 得到插件对象，再通过普通的 `context.mount()` 挂载。`setup` 可以注册 Tool、Prompt 和其他 Context 内容；`context.mount()` 返回的卸载函数保存在插件定义中，供停止或移除时使用。本实现用内置 `exec()` 执行动态代码，供教学演示，没有提供安全沙箱。

插件运行以后，它提供的工具和 Prompt 会从下一次模型请求开始出现，因为新请求会重新读取当前 Context。Session Log 同时记录 `cordis_define`、`cordis_run` 和插件挂载事件，因此可以确定模型从哪次请求开始看到新增能力。对照下图与前面的基线，可以直接看到插件列新增 `dynamic:word_count`，工具列新增 `word_count`。

## 调用新增工具以后再判断它是否有效

插件成功挂载只说明 `setup` 已经执行，不能证明新工具可以解决任务。Agent 还要调用插件提供的工具，并根据 Tool Result 判断能力缺口是否已经补足。这个最小样本调用 `word_count` 后得到 `words: 3`，证明 Agent 刚刚定义的工具已经进入 Agent Loop 并正常执行。

实验完成以后，`cordis_stop` 执行挂载时保存的卸载函数，移除插件提供的 Tool、Prompt 和其他内容，同时保留插件定义，之后可以再次运行。`cordis_undefine` 会先停止仍在运行的插件，再从定义表中删除它。最后一张图重新使用同一份列表结构；把它与第一张图对照，`dynamic:word_count` 和 `word_count` 都已消失，说明插件贡献已经撤销。

<!-- evidence {"id":"m05-removed","tab":"graph","requestStep":3,"label":"word_count 已从当前 Context 移除","description":"插件及其工具都已移除，当前 Context 的能力数量重新回到基线。"} -->

这五个工具组成一次完整的能力变化：列出现有能力，编写插件，挂载插件，调用新增工具，再停止或移除插件。新增工具进入后续模型请求，所有调用和生命周期事件进入 Session Log，Agent 因此可以用自己刚刚编写的插件继续完成任务。
