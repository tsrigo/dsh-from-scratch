# 自进化通过受控的运行时能力变更实现

本教程把运行时自进化定义为一组可检查、可验证、可撤销的能力变更。Agent 先检查当前运行时，确定能力缺口，再从受信任目录安装候选插件。实际调用结果用于决定保留当前选择或撤销安装。Agent 无法通过这套流程下载任意代码或永久修改自身。

这里不涉及模型参数学习，也不会绕过既有权限。第三章已经让运行时能够安装和卸载插件，本章把这些操作封装为模型可以调用且 Session Log 可以记录的工具。

## 变更前记录运行时基线

实验开始前，Agent 先调用 `inspect_runtime`。基线状态列出已经挂载的插件、工具、Prompt（系统提示内容）、Service（运行时服务）和依赖关系。后续对比可以确定新增工具来自哪次安装，也可以验证卸载后是否仍有残留。

## 目录限制候选能力

`install_capability` 只接受 Trusted Capability Catalog（受信任能力目录）中已经登记的名称，不接收任意代码或文件路径。未知名称和重复安装会返回明确错误。命中目录后，能力仍通过普通的 `context.mount()` 安装；安装工具保存对应的 disposer，供后续卸载使用。

<!-- evidence {"id":"m05-install-path","tab":"source","lines":[14,42],"label":"受信任目录与普通挂载","description":"检查目录限制、重复安装、插件挂载、卸载函数保存和能力移除的完整流程。"} -->

安装完成后，新增能力从下一次模型请求开始生效。Tool Schema 会增加新操作；插件贡献的 Prompt 也会进入系统规则。Session Log 同时记录插件挂载事件，因此可以确定模型从哪次请求开始接收这项能力。

## 实际结果用于验证能力

挂载成功只说明插件已经进入运行时，无法证明它能够完成当前任务。Agent 还要调用新工具，并根据可观察结果判断能力缺口是否解决。这个最小样本调用 `word_count` 后得到 `words: 3`；对应的 Tool Result 提供了能力有效的证据。

<!-- evidence {"id":"m05-verified","tab":"events","eventType":"tool/result","eventOccurrence":1,"label":"实际调用与验证结果","description":"在挂载事件之后调用 word_count，并以 words: 3 的结果验证这项能力。"} -->

实验无效、任务结束或能力仅供临时使用时，Agent 调用 `remove_capability`。插件提供的 Tool、Prompt 与其他贡献会通过同一个 disposer 一并移除。卸载后的运行时状态与基线对比，可以检查工具目录是否已经恢复。

<!-- evidence {"id":"m05-removed","tab":"graph","requestStep":3,"label":"卸载后的运行时基线","description":"对照初始状态，检查临时插件及其全部贡献是否已经移除。"} -->

新的能力缺口出现时，Agent 可以重复执行以下过程：检查现状，从受信任目录选择候选，临时安装，实际调用，再根据结果保留或撤销。每次变更都复用插件系统，写入 Session Log，并从后续请求开始生效。

Nano DSH 只演示这条最小且可解释的流程。生产系统还需要权限审批、代码签名、隔离环境和持久化策略。当前实现证明 Agent 可以进行受控的运行时适配，其能力范围仍由可信目录和现有权限限定。
