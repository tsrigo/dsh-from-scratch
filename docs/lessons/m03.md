# M03 · 能力要有主人，也要能完整离场

M02 的工具数组能工作，却回答不了三个问题：谁注册了它？卸载时还要清理什么？安装到一半失败怎么办？

最小 `Context` 不神秘。插件在 `setup()` 期间贡献服务、工具、Prompt 片段和事件 listener；每项注册立刻产生一个 cleanup effect。安装失败或卸载时，effect 以相反顺序执行，而且每个 disposer 只生效一次。重复服务、缺失服务和重名工具立即报错，半安装状态不会留下来。

事故场景现在由三块组装：provider 插件提供 `Llm` 服务，状态插件提供提交状态，事故插件消费状态并贡献两个工具、一个规则 Prompt 和 listener。`inspect()` 能显示所有归属与提供／消费关系。任务结果没有变化，但组装已经可检查、可替换、可卸载。

这正好解释网页端的四种 preset：标准模式是一套完整插件选择；PTC 在同等能力上更换工具呈现；极简模式主动删到两个编码工具；创造模式在标准组装上再加入检查、实验和创作指导。Preset 是这些选择的产品封装，不是 Agent Loop 的四种状态。Nano 不实现 preset loader。
