# 给创造模式一块受控实验区

固定组装已经可检查，恢复审计还需要验证一套透明的路由评分规则。评分能力适合临时试用，因此它不会永久进入预设配置，也不会开放 npm、命令行或任意路径加载。

常驻的 `runtime-tools` 提供三个动作：检查当前运行环境、按名称安装受信任能力、移除由它安装的能力。能力目录（catalog）只登记 `route_scoring` 和教学示例 `word_count`。安装继续调用 `ctx.mount()`，卸载使用安装时返回的同一个函数。

过程时间线会留下完整变化：安装前看不到 `score_routes`；安装后的下一次模型请求出现评分工具与规则；卸载后的请求中，两者一起消失。页面因此可以展示实验前、实验中和实验后的能力差异。

本教程把范围停在“检查组装、受控试装、验证结果”。后续实现还可以把验证过的插件选择保存为可发现、可加载的自定义预设配置。
