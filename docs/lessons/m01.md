# M01 · 先让循环转起来

问题不是“模型会不会推理”，而是它怎样把一句判断变成一个可验证的动作。

我们先故意不用插件和会话数据库。`Agent` 把 system prompt、已有消息、工具 schema 和当前 step 的动态信息交给统一的 `Llm` 接口。模型返回工具名与 JSON 参数；Harness 用 Ajv 校验，串行执行，再把结果作为 `tool` 消息追加。只要还有工具调用，就产生下一 step；没有工具调用，整个 turn 才结束。

火星事故包只有两个有边界的动作：读取固定数据、提交固定结构的方案。没有 Shell，也没有任意文件路径。fake provider 用同一个协议稳定完成三步：读取、提交、收尾；DeepSeek provider 只负责映射 Chat Completions 格式，不拥有循环。

## 标准模式与 PTC 不是两套能力

标准模式把每个工具 schema 逐个呈现，模型逐次返回普通 tool call。PTC 模式保留标准模式的全部能力，只把呈现层换成 Code Mode SDK，让模型写 TypeScript 来组合循环、条件和多步调用。Nano 只运行前一种路径；`PTC_PRESENTATION_EXAMPLE` 是静态对照文本，不存在 `run_code`，也不会执行模型生成的程序。
