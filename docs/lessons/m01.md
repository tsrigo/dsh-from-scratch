# Agent Loop 按模型反馈重复执行步骤

一次模型调用只产生一次回复。Agent（智能体）处理任务时，模型可能需要先确定缺少的信息，调用工具取得结果，再根据结果选择下一步。工具调用次数由模型在执行期间根据已有结果决定，因此运行时需要重复执行一组步骤，直到模型给出最终回复。

## 模型选择动作，Harness 校验并执行

DeepSeek Harness（DSH）把一次连续执行称为 Turn（轮次）。Turn 从 Agent 接收一批已经准入的输入开始，在这批输入不再产生后续工作时结束。Nano DSH 用一条用户消息组成这批输入。Turn 中的每次模型请求及其触发的工具执行构成一个 Step（步骤）。

每个 Step 开始时，Harness 把系统规则、当前工具、已有历史和本步说明组成统一请求，再交给模型。模型可以返回普通文字，也可以返回一组 Tool Call（工具调用）。每个 Tool Call 包含工具名称和参数，Harness 根据这些内容启动对应操作。

Harness 收到 Tool Call 后查找工具、校验参数并执行。未知工具、参数错误和执行异常都会转换为模型可读的结构化结果。模型负责选择动作，运行时负责判断动作能否执行并完成具体操作，两者的职责由工具接口分隔。

## 工具结果进入下一次请求

工具执行完成后，任务可能仍需继续。Harness 把 Tool Result（工具结果）及其调用编号写入历史，然后进入下一个 Step 并再次请求模型。模型可以读取刚才提出的调用和运行时返回的实际结果，据此修改计划、调用其他工具或给出最终回答。

右侧请求对比只展示这一处变化。第一份请求要求模型取得时间；第二份请求保留原有规则和问题，并在末尾追加工具调用与查询结果。Agent Loop 通过这次追加把执行结果用于下一步判断。

## Turn、Step 与停止条件

Nano DSH 的 `runTurn()` 每次接收一条用户消息，并在同一个 Turn 中连续执行多个 Step。模型返回 Tool Call 时，Harness 执行工具并进入下一步；模型返回最终文字时，当前 Turn 结束。这条路径集中展示模型请求、工具执行和结果反馈之间的循环关系。

完整 DSH 会在每个 Step 结束时检查当前 Turn 是否仍有待处理的工具结果或新输入。Nano DSH 为 Turn 设置 Step 数量上限；工具失败会作为结果返回给模型，使模型可以调整处理方式，达到上限时则明确终止运行。Provider（模型服务适配器）负责把统一请求转换为具体模型接口所需的格式并处理流式返回，Agent Loop 负责推进 Turn 和 Step。

DSH 的 Agent Loop 依次完成请求组装、模型调用、工具校验与执行、结果追加，并根据新的模型输出继续或停止。后五章分别管理这组循环的输入、能力、记录、运行时变更和跨轮协调。
