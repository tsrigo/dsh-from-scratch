# Agent Loop 按模型反馈重复执行步骤

一次模型调用只产生一次回复。Agent（智能体）处理任务时，模型可能需要先确定缺少的信息，调用工具取得结果，再根据结果选择下一步。工具调用次数无法预先确定，固定工作流也无法覆盖模型根据结果作出的所有选择，因此运行时需要重复执行一组步骤。

## 模型选择动作，Harness 校验并执行

一个 Turn 表示一次用户任务。DeepSeek Harness（DSH）先把系统规则、当前工具、已有历史和本步说明组成统一请求，再交给模型。模型可以返回普通文字，也可以返回一组包含名称和参数的 Tool Call（工具调用）。Tool Call 只描述待执行动作，不会直接执行代码。

Harness 收到 Tool Call 后查找工具、校验参数并执行。未知工具、参数错误和执行异常都会转换为模型可读的结构化结果。模型负责选择动作，运行时负责判断动作能否执行并完成具体操作，两者的职责由工具接口分隔。

## 工具结果进入下一次请求

工具执行完成后，任务可能仍需继续。Harness 把 Tool Result（工具结果）及其调用编号写入历史，然后进入下一个 Step 并再次请求模型。模型可以读取刚才提出的调用和运行时返回的实际结果，据此修改计划、调用其他工具或给出最终回答。

右侧请求对比只展示这一处变化。第一份请求要求模型取得时间；第二份请求保留原有规则和问题，并在末尾追加工具调用与查询结果。Agent Loop 通过这次追加把执行结果用于下一步判断。

## Turn、Step 与停止条件

在这份教学实现中，一个 Turn 表示一次用户任务；一次模型请求及其触发的工具执行构成一个 Step。一个 Turn 可以包含多个 Step。模型继续调用工具时，Harness 会进入下一步；模型不再调用工具时，当前回复结束这个 Turn。

循环还需要运行时边界。工具失败会作为结果返回给模型，使模型有机会调整处理方式。连续 Step 达到上限后，Harness 会明确终止运行，避免无限消耗资源。Provider（模型服务适配器）只负责把统一请求转换为具体模型接口所需的格式，可以替换，不控制 Agent Loop。

DSH 的 Agent Loop 依次完成请求组装、模型调用、工具校验与执行、结果追加，并根据新的模型输出继续或停止。后五章分别管理这组循环的输入、能力、记录、运行时变更和跨轮协调。
