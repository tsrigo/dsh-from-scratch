# 用过程记录还原任意一步

会话事件（Session Event）是一张按顺序编号的过程收据，例如用户发来消息、模型请求工具、工具返回结果。记录采用只追加方式，已经发生的内容不会被覆盖。

会话日志（Session Log）按时间装订所有收据。用户消息、模型回答、工具调用、完整工具结果、轮次边界和插件变化都进入同一条日志。每个 `request/header` 事件保存当时的模型、系统规则、工具说明、动态上下文和投影设置。

`buildRequest(events, stepId)` 读取目标请求头之前的事件，按顺序还原消息，再应用前一章的裁剪规则。测试会逐步对比重建结果与实际发送内容。执行轨迹（Trace）是这份日志的阅读视图，页面用时间线呈现同一组事件。

上下文摘要点也会写成事件。它声明摘要覆盖到哪条记录；后续请求从摘要和新事件继续拼装，早期原始记录仍然保留，因此历史步骤仍可按当时状态还原。

这一章把“模型当时看到了什么”和“系统当时做了什么”接到同一份可核验记录上。
