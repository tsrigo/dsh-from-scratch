# M04 · 发生过的事，只有一份

到 M03 为止，Agent 仍藏着一个 `messages` 数组。Trace 和请求可以看起来一致，却没有共同的权威来源。

M04 把它换成只追加的 `SessionLog`。用户消息、模型回答、工具调用、完整工具结果、turn／step 边界和插件变化都成为事件。每个 `request/header` 只冻结当时的 provider、model、编译后 Prompt、tool schemas、动态上下文和投影设置；它不复制历史消息。

`buildRequest(events, stepId)` 读取目标 header 之前的事件，按顺序还原消息，再应用 M02 的裁剪规则。测试对每个 step 断言“重建请求深度等于实际发送请求”。网站 Trace 也由 `replayTrace()` 读取同一组事件，不维护第二份漂亮但可能漂移的数据。

摘要检查点同样是事件。它声明覆盖到哪个 event id，并为模型投影提供确定性摘要；早期原始事件没有被删除。检查点之后的请求从摘要加新事件重建，检查点之前的任意请求仍然可以按当时的 header 和事件前缀还原。

这里没有 JSONL。我们筛选后确认，进程重启并不是离线恢复审计的必要教学问题；为它保留 writer 或配置只会制造假范围。
