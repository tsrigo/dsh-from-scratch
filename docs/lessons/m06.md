# 让任务跨过 Turn 继续

第一章的 Turn 在模型不再调用工具时结束。第五章结束时，Agent 刚装好工具又卸掉，Turn 停下来。但任务可能还没完：整理三条发布说明，第一轮收集到两条，还缺一条。Turn 结束不等于任务完成。谁决定再来一轮？这一章回答：Goal 怎样保存任务状态，谁来决定继续或停止。

## 6.1 Goal 保存状态，驱动器做决策

DSH 把 Goal（目标）作为同一个 Session（会话）中可持续保存的状态。Goal 记录 objective（目标内容）、phase（阶段）、已经启动的 Goal Round（目标续行轮次）数量和轮数上限。Goal Round Driver（目标续行驱动器）在 Agent 空闲时检查 Goal：phase 为 active、续行已经启用且仍有剩余轮数时，它向同一个 Session 追加一条带目标和轮次编号的消息，再启动一个普通 Turn。

Nano DSH 用 `LongTaskRunner` 浓缩这套关系。`LongTaskState` 保存 objective、status、已经启动的轮数、最大轮数和最近一次状态变化的原因；两个 `RoundDefinition` 保存每轮的名称和输入；`runRound` 启动第一章的普通 Agent Turn。每个 Round 就是一次普通 Turn 加上一条追加的目标消息，前五章的机制原样复用。

## 6.2 下一轮沿用同一个 Session

`LongTaskRunner` 不直接请求模型，也不执行工具。它在每轮开始时调用外部传入的 `runRound` 函数；本教程的 `runRound` 使用同一个 Agent、Context 和 Session Log 启动新的 Agent Turn，因此前一轮的插件、消息、工具结果和工作区变化都会继续保留。

请求对比卡展示两轮请求的差异。第二份请求共约 50 token，开头约 19 token 与第一份相同，包含长期目标与第一轮的进展记录；之后追加第二轮任务。第二轮因此在已有进展上继续，不需要重建一份对话历史。

## 6.3 每轮结束后检查是否继续

每轮结束后，`runRound` 返回 `RoundResult`（单轮结果）：progressed 表示这一轮是否产生预期进展，completed 表示整个 Goal 是否完成，blockedReason 记录无法继续的原因。Nano DSH 根据这三个字段把状态更新为 completed、blocked 或 max-rounds；取得进展但尚未完成时保持 active，启动下一轮。

事件卡展示这个最小样本的完整过程：Goal 创建、第一轮启动、第二轮启动、completed 状态写入，停止理由是三项均已写入交付物。完整 DSH 的 Goal 还有 paused 阶段，模型通过 `update_goal` 报告完成或阻塞，每次状态变化都保存进 Session Log。

## 6.4 六章合起来看

把六章叠起来：Agent Loop 管理一次工具往返（第一章），投影控制每次请求的长度与顺序（第二章），插件组装与撤销运行能力（第三章），Session Log 记录并重建一切（第四章），Agent 在执行中补齐能力（第五章），Goal 与 Round 让任务跨过 Turn 继续（第六章）。输入、能力、记录与续行都服务于同一条循环。

第六章增加的是 Agent Loop 外面的续行机制：Goal 保存跨 Turn 的目标状态，Round 表示一次续行，驱动器在每轮结束后决定是否再启动一个 Turn。到这里，六章覆盖了 DSH 运行机制的一条完整主线：从一次模型调用，到一次可靠的长程执行。
