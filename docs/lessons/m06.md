# 用 Goal 在同一个 Session 中持续推进任务

第一章的 Agent Loop 管理一个 Turn：接收本轮输入，反复请求模型并执行工具，直到模型不再调用工具。Turn 结束表示这次执行已经停下来，但一个长期目标可能仍然需要继续处理。

DeepSeek Harness 把 Goal（目标）作为同一个 Session（会话）中可持续保存的状态。Goal 记录 `objective`（目标内容）、`phase`（阶段）、已经开始的 Goal Round（目标续行轮次）数量和轮数上限。Goal Round Driver（目标续行驱动器）在 Agent 空闲时检查 Goal：`phase` 为 `active`、续行已经启用且仍有剩余轮数时，它会向同一个 Session 追加一条带目标和轮次编号的 `<goal_round>` 消息，再启动一个普通 Turn。新的 Turn 继续使用当前工作区、工具结果和会话历史。

Nano DSH 用 `LongTaskRunner` 浓缩这套关系。本章使用一个整理三条发布说明的任务：第一轮收集两条已有信息，第二轮补全最后一条并交付。`LongTaskRunner` 把目标、状态和轮数保存在 `LongTaskState` 中，用两个 `RoundDefinition` 保存每轮的名称和输入，再通过 `runRound` 启动普通的 Agent Turn。这个最小样本展示一个 Goal 怎样跨越多个 Turn，以及每轮结束后由谁决定继续或停止。

## LongTaskRunner 保存目标并启动 Round

`LongTaskState` 保存 `objective`、`status`、已经启动的轮数、最大轮数和最近一次状态变化的原因。`LongTaskRunner` 在开始时写入 Goal 创建事件；状态为 active 且仍有可用 Round 时，它取出下一份 `RoundDefinition`，记录 Round 编号与名称，再调用 `runRound`。

每轮结束后，`runRound` 返回 `RoundResult`（单轮结果）。`progressed` 表示这一轮是否产生了预期工具结果或工作区变化，`completed` 表示整个 Goal 是否完成，`blockedReason` 记录无法继续的原因。Nano DSH 根据这三个字段把状态更新为 `completed`、`blocked` 或 `max-rounds`；取得进展但尚未完成时，状态保持 `active` 并启动下一轮。

完整 DeepSeek Harness 使用 `active`、`paused`、`blocked` 和 `complete` 表示 Goal 的 `phase`，并由 Goal Round Driver 根据 `phase`、续行启用状态和轮数上限决定是否准入下一轮。Nano DSH 的 `LongTaskState` 与 `RoundResult` 把同一组继续／停止判断集中到一段便于阅读的控制流中。

## 下一轮沿用同一个 Session 的已有记录

`LongTaskRunner` 不直接请求模型，也不执行工具。它在每轮开始时调用外部传入的 `runRound` 函数。本教程的 `runRound` 使用同一个 Agent、Context 和 Session Log 启动新的 Agent Turn，因此前一轮的插件、消息、工具结果和工作区变化都会继续保留。

完整 DeepSeek Harness 的 Goal Round Driver 也在同一个 Session 中续行。它为每轮追加目标和轮次编号，让模型根据已有历史判断下一步。Nano DSH 为确定性演示准备了收集已有信息、补全并交付两份阶段说明，使程序可以自动检查每一轮的预期结果。

右侧比较两份模型请求。第二份请求先保留长期目标和第一轮的进展记录 `已找到两项，仍缺一项`，然后追加第二轮任务。第二轮因此沿用已有进展，不需要重新建立一份对话历史。

Nano DSH 把 Goal 创建、Round 启动和最终状态变化写入 Session Log；每轮使用的 Tool、Prompt、模型回复和工具结果也写入同一份日志。Goal 事件解释协调器为什么继续或停止，Turn 和 Step 事件记录 Agent 实际完成了什么。

完整 DeepSeek Harness 使用 `goal/change` 保存 Goal 快照和 `revision`（版本号），并用带 Goal 来源的 `user/message` 记录已经准入的 Goal Round。目标状态与执行历史仍然以同一份 Session Log 为准。

## 每轮结束后检查是否继续

完整 DeepSeek Harness 在 Agent 空闲时检查 Goal。模型已经把 `phase` 更新为 `complete`、`blocked` 或 `paused` 时，驱动器停止续行；Goal 保持 `active`、续行已经启用且还有剩余轮数时，驱动器启动下一轮。模型通过 `update_goal` 报告完成或阻塞，Session Log 保存每次状态变化。

Nano DSH 把这项检查写成 `LongTaskRunner` 中的一组明确分支：整个目标已经完成、当前轮没有产生预期进展、执行函数返回阻塞原因、缺少下一阶段或达到最大轮数时停止；当前轮取得进展且 Goal 尚未完成时继续。发布说明样本先记录已经找到的两条信息，再启动第二个 Round 补全第三条，并把 Goal 更新为 `completed`。

第六章增加的是 Agent Loop 外面的续行机制：Goal 保存跨 Turn 的目标状态，Round 表示一次续行，Session Log 保存已有进展，驱动器在每轮结束后决定是否再启动一个 Turn。
