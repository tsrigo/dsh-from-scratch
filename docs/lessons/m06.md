# Goal 和 Round 在多个 Turn 之间保存任务状态

第一章的 Agent Loop 管理一个 Turn 内的行动。模型停止调用工具时，当前 Turn 随之结束，整个目标可能仍未完成。研究、迁移或多阶段交付通常需要分段推进，并在一次自然停顿后再次启动 Agent。

DSH 在 Agent Loop 外增加 Goal（长期目标）与 Round（阶段轮次）。Goal 保存相对稳定的目标和整体状态；Round 表示针对该目标进行的一次阶段性推进；Round 内运行普通的 Agent Turn，而 Turn 由若干 Step 组成。这四个层级分别管理不同时间尺度的状态和停止条件。

## 外循环决定是否启动下一轮

Goal 至少保存 objective（目标内容）、status（状态）、已启动轮数、最大轮数和最近一次状态理由。协调器只在状态为 active（进行中）时继续。每轮开始前记录 Round 编号与阶段说明，再调用内层 Agent。文件读取、工具调用和结果反馈仍由前五章的机制处理。

协调器接收一份结构化 RoundResult（单轮结果），其中分别记录是否取得可观察进展、是否已经完成以及是否遇到阻塞。外循环据此把状态设置为 completed（已完成）、blocked（受阻）、active，或在轮数边界设置为 max-rounds（达到轮数上限）。

## 续行复用目标、运行时和会话日志

LongTaskRunner 只接收一个 `runRound` 回调，不强制回调启动 Agent。本教程的组合层在回调中复用同一个 Goal、运行时 Context 和 Session Log，再启动普通的 Agent Turn。稳定目标不会被上一轮的临时说明覆盖，前一轮产生的消息和工具结果继续保留。

右侧比较两份请求。第二份保留第一轮的目标和进展记录 `已找到两项，仍缺一项`，随后追加第二轮任务。这段连续历史说明下一轮会使用已有进展继续处理目标。

外层事件只记录 Runner 直接观察到的状态变化：Goal 创建、两次 Round 启动和最终 completed。第一轮的具体进展保存在请求历史中；Goal 事件记录协调器停止的原因。两类记录描述不同层级的事实。

## 续行需要明确的停止条件

长程运行如果在没有进展时继续，会反复消耗资源。任意一轮没有可观察进展、返回阻塞原因、达到最大轮数或已经完成时，协调器都应停止，并把原因写回 Goal 与 Session Log。下一轮只能在当前轮取得进展且目标仍未完成时启动。

当前 Nano DSH 在单个进程中演示跨 Round 续行，没有实现进程重启后的 Goal 恢复、定时唤醒、后台 Job（任务）或 Subagent（子智能体）。跨越这些边界还需要持久化 Goal 与 Session Log，并由调度器重新启动任务。

DSH 保存长期目标和每轮进展，在每个有界 Round 结束后检查完成、受阻、无进展和轮数上限四类条件。条件允许时，协调器使用已有状态启动下一轮；达到任一停止条件时记录原因并结束 Goal。
