# M06 · 长程不是无限循环

前五章解释了一个 turn 内的 Harness。恢复审计却天然有三个不同的工作阶段：先调查，再评分，最后清理实验并提交。把它们挤进一次连续回答，会让“做到哪了”和“为什么继续”变得含糊。

`LongTaskRunner` 只保存教学真正需要的状态：目标、`active/completed/blocked/max-rounds`、已经开始的 Round 数和上限。每轮调用的是同一个 Agent；Agent 仍使用同一 Context、上下文投影和 Session Log。Goal 与 Round 变化也写入同一事件流，所以网站可以把跨轮进度放回完整 Trace。

续行需要实际证据。survey 轮必须出现事故包结果，score 轮必须出现评分结果，submit 轮必须被 verifier 接受且临时插件已卸载。某轮没有观察到预期进展就 blocked；达到轮次上限仍未完成就显式 `max-rounds`，不会偷偷再跑一次。确定性测试覆盖 completed、blocked 和上限三种停止条件。

这不是完整 Goal 服务，更不是调度系统。没有后台 Job、Schedule、Todo、Subagent 或 Workflow；只有一个让同一任务跨 Round 继续、且能说明停止原因的小协调器。
